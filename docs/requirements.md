# アリガトサン社内FPS MVP 要件定義書

**プロジェクト名**: （未定 / 仮称: ArigatoArena）
**開発期間**: 2日
**開発体制**: Claude Code subagent並列開発
**目的**: 社内イベント用のオンライン対戦FPS

---

## 1. ゲーム仕様

### 1.1 基本ルール

| 項目 | 内容 |
|---|---|
| ゲームモード | チームデスマッチ |
| プレイヤー数 | 5v5（最大10人） |
| 試合時間 | 3分 |
| 視点 | FPS（一人称固定） |
| 勝敗条件 | 3分経過時点のチーム合計キル数が多い方が勝利。同数の場合は引き分け |

### 1.2 戦闘システム

**HP/ダメージ**
- 基礎HP: 100
- ヘッドショット判定あり（頭部ヒットボックス）
- 部位別ダメージ倍率: 頭 ×2.0 / 胴 ×1.0 / 脚 ×0.7（要バランス調整）

**武器3種**

| 武器 | 特性 | 想定パラメータ |
|---|---|---|
| アサルトライフル (AR) | 中距離万能 | ダメージ25、連射速度600rpm、マガジン30発 |
| ショットガン (SG) | 近距離一撃 | ダメージ15×8ペレット、連射200rpm、マガジン6発 |
| サブマシンガン (SMG) | 近距離乱射 | ダメージ18、連射900rpm、マガジン25発 |

※数値はDay2のプレイテストで調整。

**リロード**
- マガジン制 + 手動リロード（Rキー）
- リロード中は射撃不可、移動は可能

### 1.3 移動・操作

- 姿勢: 立ち固定（しゃがみなし）
- 移動: WASD（歩行）
- スプリント: Shift押しっぱなしで加速
- ジャンプ: Space（連続ジャンプ不可、接地必要）
- 視点: マウス（FPS標準）
- 射撃: 左クリック
- リロード: Rキー
- 武器切替: 1/2/3 or マウスホイール

### 1.4 リスポーン

- 死亡後3秒で自動リスポーン
- チーム陣地側のランダムスポーン地点に出現
- 出現直後2秒間の無敵時間あり（スポーンキル防止）

## 2. マップ仕様

| 項目 | 内容 |
|---|---|
| レイアウト | 3レーン構造（上/中/下ルート、CS風） |
| サイズ | 約60m × 40m |
| テーマ | 廃墟・ノイズ系（コンクリート、錆、瓦礫） |
| 対称性 | 左右対称（公平性確保） |
| マップ数 | 1枚（MVP） |

**構成要素**
- 中央レーン: 開けた直線、長距離戦
- 上レーン: 高所、足場 + ジャンプ要素
- 下レーン: 屋内通路、近距離戦
- 各チーム陣地: スポーン地点3〜5箇所をランダム選択

## 4. UI・フロー仕様

### 4.1 参加フロー

```
[ホスト]
  ロビー画面 → 「ルーム作成」ボタン
    → ルームコード生成 (6桁英数字)
    → コードをSlack/口頭で共有

[参加者]
  ロビー画面 → 名前入力 → ルームコード入力
    → ルーム参加 → キャラ選択 → 待機

[ホスト]
  チーム振り分け画面 → 「シャッフル」or 手動調整
    → 「試合開始」ボタン押下
    → 3カウントダウン → 試合開始
```

### 4.2 画面構成

1. **ロビー画面** (Next.js): ルーム作成/参加、名前入力
2. **待機画面** (Next.js): メンバー一覧、キャラ選択、チーム振り分け
3. **試合画面** (R3F): HUD（HP/弾薬/キル数/タイマー/ミニマップ）
4. **試合結果画面** (Next.js): K/D/A/HS数のスコアボード、MVP表示

### 4.3 認証

- ログインなし
- 名前入力のみ
- ルームコード参加方式

### 4.4 試合結果

| 項目 | 表示 |
|---|---|
| 勝敗 | チーム勝利/敗北 |
| 個人スコア | キル数、デス数、アシスト数、ヘッドショット数 |
| MVP | キル数最多のプレイヤー |
| 永続化 | Supabaseに保存（後日の社内ランキング集計用） |

## 5. 技術仕様

### 5.1 対応環境

- **対応ブラウザ**: デスクトップChromeのみ（動作保証）
- **解像度**: 1920×1080推奨、最低1280×720
- **回線**: 社内LAN前提（低遅延想定）

### 5.2 音声

- BGM: 試合中ループ1曲（生成 or フリー素材）
- SE: キル音のみ（足音・リロード音はMVP範囲外）
- ボイスチャット: なし
- テキストチャット: なし

### 5.3 アーキテクチャ

```
┌─ クライアント (Chrome) ─────┐
│  Next.js 15 (App Router)    │
│  React Three Fiber          │
│  @react-three/rapier        │
│  Zustand (状態管理)         │
│  PartyKit Client SDK        │
└─────┬──────────────┬────────┘
      │ HTTPS        │ WebSocket
      ↓              ↓
┌─ Vercel ──┐   ┌─ PartyKit ─────┐
│ Next.js   │   │ Cloudflare DO  │
│ SSR/API   │   │ 20Hz tick      │
└─────┬─────┘   │ サーバー権威   │
      │         │ ヒット判定     │
      ↓         └────────┬───────┘
┌─ Supabase ──────────────┴───┐
│ Postgres (users/matches)    │
└─────────────────────────────┘
```

### 5.4 サーバー権威の範囲

**サーバー側で判定**
- プレイヤー位置（クライアント入力 → サーバー検証）
- ヒット判定（レイキャスト）
- HP管理・キル判定
- リスポーンタイマー
- 試合タイマー

**クライアント側で処理**
- 描画・補間
- 入力受付
- エフェクト・サウンド

### 5.5 通信仕様

- **同期レート**: 20Hz (50ms tick)
- **プロトコル**: WebSocket（PartyKit）
- **メッセージ形式**: JSON or MessagePack
- **クライアント予測**: なし（MVP簡略化）
- **補間**: 100msバッファでサーバー状態を補間描画

## 8. 成功定義

**最低限（必達）**
- 10人が同時にChromeから参加できる
- 3分間、撃ち合いができて、キル数が記録される
- 試合終了後に結果画面が出る
- 大きなクラッシュ・同期ズレなく完走する

**目標**
- メンバーオマージュキャラが「あ、〇〇さんだ」と認識できる
- 撃ち心地が「楽しい」と言える
- 社内イベントで歓声が上がる

**理想**
- 複数試合連続でプレイされる
- 「もう一回やりたい」と言われる
- 戦績がSlackで共有される
